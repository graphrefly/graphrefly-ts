# 记录路径单因素对照（设计稿）

2026-09-12 · 基线 `1c74c254` · owner/work：`graphrefly-ts:CAUSAL-PRESET-ASSEMBLY-TS`。
用户同意先细化设计。本轮不实现、不采集，不改变 D168/D169 的方法或门槛。

## 问题与唯一干预

[上一轮](diagnostic-capture/README.md) 观察到第一批 CPU 与经过时间同时较高，
但未定位到构造、VM 或记录/清理。现在只问：**把样本记录工作移出构造序列，
是否改变后续构造的耗时和整个序列的 CPU？**

原路径在 `scripts/fixtures/spending-preset-performance-worker.ts:222`：

```js
samples.push(v);
appendFileSync(samplesPath, `${JSON.stringify(v)}\n`);
```

它同时包含序列化、字符串分配和同步追加，不能称为纯磁盘实验。若保留即时序列化而
延后写入，会额外保留所有字符串，改变内存状态。因此推荐以下精确对照：

| 条件 | 每次 record | 最后一次清理及测量 checkpoint 之后 |
|---|---|---|
| EAGER | 原样 push、stringify、append | 无延后样本记录 |
| DEFERRED | 仅原样 push | 按 samples 原顺序逐个 stringify、append |

成功时两边均有2,400次 push、2,400次 stringify 和2,400次 append，输出字段、JSONL格式
与顺序相同。不增加字符串缓存、不使用 join 合并写入、不改变系统调用次数、不删掉输出。
操作的时间位置是唯一指定的干预；它带来的 VM/GC、缓存和错误时机变化是该干预的后果，
不能声称这些后果被隔离成纯 I/O 成本。

**范围保持：** 当前同一 reference/reference-copy、cold-P2-summary、原 U/V 三批两槽、
100 warmup + 300 measured、原预检/内存读取/让出/构造/清理、两份模块命名空间与 Node flags。
不比较 library candidate，不改变构造函数、C 注册机制、输入或生命周期。

## 观测与公平解释

两个条件都使用上一轮已资格的 block CPU checkpoint，不安装新的 GC observer；
原 native trace flags 在两边保持一致，其时钟仍不用于归因。
不把上一轮 BASE/CPU 数据拼进本轮对照或用作配对分母。

记录并保留三类成本：

1. 原始构造窗口：每个 measured block 的 p50、nearest-rank p95、构造总和。
2. 原始共同跨度及 CPU checkpoint：描述运行序列。DEFERRED 将记录工作移出了这段，
   因而 CPU/跨度降低本身并不能证明总工作减少，更不能单独作为“构造被干扰”的证据。
3. 包含全部输出工作的整体区间：两个条件都在第一个 warmup 前、最后输出完成后
   读取同样的 wall/CPU 边界。DEFERRED 另报 flush 区间，EAGER 明确为无独立 flush。
   这些整体数字不是 cold 构造预算，也不是用户启动时延承诺。

新增整体 checkpoint 在两个条件中位置一致；不放入构造 start/end 内。不从经过时间减去
进程 CPU 推算等待，不把整体 CPU 当作构造独占 CPU。flush 也可能影响退出阶段的资源峰值，
因此父监督器持续到子进程退出，不能在最后一个构造结束时停止资源检查。

## 完整性与失败路径

DEFERRED 依靠已有 samples 对象数组，不修改 record 对象来补造历史。实现前须证明 cold
样本对象和可达数组/内存快照不会在 push 之后被清理或后续迭代修改；否则这一实现不成立，
停止准备并报告，不能在计时路径偷偷加入 deep clone/freeze 来修补。

DEFERRED 的延后写入在外层收尾中执行：正常完成和可捕获失败都按顺序写出已有前缀。
flush 失败时保留此前成功写出的行，不从头重写、不补齐或重试；原业务/清理错误与写入错误
同时保留。仅所有样本、清理和写入都成功后生成 completion。

父进程超限强停、崩溃或不可捕获错误可能使尚未 flush 的样本丢失。这是 DEFERRED 的真实
耐故障性代价，不能要求内存数据一定可恢复。保留原 stderr/退出/资源记录，整个尝试 invalid，
后续保持 not-run；不追加救援日志或新采样。EAGER 在较早位置暴露写入失败，二者不同的失败
时机必须报告，不能用成功路径等价来掩盖。此实验不会自动推广为正式日志策略。

## 固定采集量与资源

拟议一次：**4轮 × 2条件 × 2方向 = 16个串行新进程**。每轮四个组合各一次，轮内完整
顺序在唯一 reservation 中随机固定，不能按观察结果重排。

- 每进程3批 × 2槽 × 400 = 2,400样本；总计 **38,400**。
- 9,600 warmup、28,800 measured；96个 measured block。
- 每进程两份原三臂预检：32次调用、96个计时外实例；工具资格探针另外明确列账。
- 30秒/子进程、15分钟/整个尝试；观测RSS 256 MiB/子进程、运行目录256 MiB。
  目标100 ms观测，间隔>1秒停止；包含 flush、关闭与退出，不能豁免尾部。
- 一次审批 claim，准备失败也消费；原样保留失败，无自动重试、补样或扩预算。

绑定上一轮的当前源码闭包及 Node 24.18.0 二进制，原 flags 和显式环境沿用资格包。
新增派生源、独立 checker/verifier 必须另行绑定；旧工具资格不覆盖新记录策略。
本设计没有划拨任何正式矩阵、M面板、provider/live/spend或第二项 library 优化。

## 固定分析与决策规则

同轮、方向、批次、位置配对 DEFERRED/EAGER，共48个 measured 对比。p50取中间两项平均，
p95取第285/300个值。列出所有原始量、每个比值及每坐标四轮的范围；不只给平均数。
整体区间按轮和方向给出8个配对值；warmup单列，不删除首批。
不设新的显著性门槛，不用5%或1.20给本诊断判资格通过。

为防止事后挑选“有效”的坐标，预先固定如下有限行动规则：

| 结果 | 本批结论与后续上限 |
|---|---|
| 首批的4个方向/位置坐标，其四轮构造 p95 和构造总和比值都<1 | 有一致的构造窗口变化，支持记录路径影响后续构造；先审阅评测记录策略及其损失样本风险，不能直接称为 library 提速或正式方法修复。 |
| 只有序列 CPU/跨度下降，构造窗口没有上述一致变化 | 主要能确认工作被移出了观测区间；不能证明它解释了构造慢尾部，不因这点改评测方法。 |
| 坐标方向混合、相等或没有复现原现象 | 不支持优先沿记录方向继续优化；本次到此结束，不增加轮次追求一致。 |
| 超限、样本丢失或错误 | invalid，交付失败位置与完整可保留证据；不作性能结论。 |

首批规则只是一项描述性行动约束，不是统计显著性或因果充分性证明；其余两批仍完整公开。
即使所有首批方向一致，整体CPU/经过时间若更差，也必须显式保留；不能用移动工作位置隐藏总成本。
细小但一致的变化仍需说明绝对幅度，不能据“都<1”自动采用新策略。

## 工具准备的验收

下一批建议先实现私有派生路径并离线资格检查，之后提交准备包；真实性能采集单独批准。

- 独立源差异白名单：只移动 stringify/append；push、构造、清理、checkpoint不被删改，
  不合并写入、不偷偷序列化两次，BASE旧证据和D169工具不覆盖改写。
- 加载计数stub，验证全部16个计划坐标、每个条件2,400次写入、DEFERRED不早写、EAGER
  不晚写，以及原始样本内容在清理前后保持一致。额外检查真实 cold 对象的可变性前提。
- 故障注入：第一个/中间/最后一个序列化或写调用失败、业务与flush同时失败、cleanup失败、
  强停导致未落盘、重复flush、伪造completion；不得吞错或补造样本。
- 独立复算器区分构造窗口、共同跨度、checkpoint、flush和整体区间；用非1手算数据拒绝
  偷换分母或忽略flush。16坐标、完整样本、原样前缀、进程身份/来源和资源门槛分别核对。
- 原样本与新记录文件的等价检查只比在相同输入记录下的序列化内容；真实两条件的时间和
  内存读数当然可能不同，不能要求这些数值相等，也不能为匹配而改写。

## Q5–Q9

**Q5 抽象位置：** 私有评测记录安排，复用原样本数组和写函数；不新增公共profiler、
用户配置或通用日志框架。真实前例就是现有 worker 的 record 函数。

**Q6 不变量和长期代价：** 固定工作量、完整输出、精确清理、错误并存。DEFERRED降低
失败时的证据可恢复性；只有诊断收益明确后才值得讨论其正式用途，不能默认为长期方案。

**Q7 简化和可组合性：** 不添加字符串队列、不改变写调用次数、不进入 graph 执行函数。
identity、graph-owned lifecycle、退订不结算义务、retained evidence 和分级入口不变。

**Q8 替代方案：** 保留即时序列化而缓存字符串，更接近写入位置对照，但增加保留对象；
改为单次批量写减少调用数量，同时改变多个因素；关闭日志会丢掉证据。推荐移动整个原记录
片段，并明确结论只属于记录路径整体，不归结为磁盘单因。

**Q9 推荐和剩余风险：** 覆盖单一指定干预、工作量账目、构造边界和产品零新增负担；
仅部分覆盖VM状态可比性，不能覆盖纯I/O归因或强停样本完整性。接受这些局限用于一次有限
诊断。若收益不明确，就结束此方向；不因完成设计而派发采集或修改现行验收方法。
