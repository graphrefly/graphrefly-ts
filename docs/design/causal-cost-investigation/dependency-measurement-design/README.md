# Single-version process comparison — review draft

本批为原 `graphrefly-ts:CAUSAL-PRESET-ASSEMBLY-TS` 的私有诊断设计草案。
不修改 library，不执行准备探针或 consumer，不取代 graphrefly-ts:D168/D169 的正式方法，
不重开 registry 的 A/B/C 选择。以下只比较测量方法，待用户审阅后才进入私有工具准备。

## 1. 要回答的问题

在同一 P2 summary consumer、同一 Node 和有限的进程历史下，单循环 eager 初始化
相对原初始化，是否呈现可重复的构造中心耗时下降？构造慢尾与整个业务动作成本是否
分别呈现下降、上升或无法判断？各项分别报告，不能合成一个“优化通过”。

它测量的是固定预检和 warmup 后反复创建新 graph 的成本，不是首次模块导入、
首次 graph、长期 steady state、单 graph 内存、正式 preset/reference 预算或已知 GC 根因。
B/C 仍为 8253488b / 9c30967c 的完整冻结提交，P2 输入与八个外部时钟边界不变。

已有证据见 [顺序审计](../dependency-order-audit/README.md)：构造 p50 的16次比值均下降，
p95 同代码控制在开头偏移，位置方向不统一。这是提出新设计的动机，不能成为新方法的
资格样本；旧数据不参与新统计，也不会改写旧 inconclusive。

## 2. 选择：每个进程只加载一个版本

| 备选测量形态 | 获得什么 | 代价及缺口 |
| --- | --- | --- |
| 保留双模块，增加平衡交换与重复 | 改动小，延续旧驱动 | 两个模块与先后历史仍混合，重复不会自行消除 |
| **推荐：单模块新进程，时间相邻四进程分组** | 去掉进程内第二模块/第二位置，共用同一模块路径 | 跨进程调度与非线性时间变化仍存在；需要严格同版本控制 |
| 单独 factory 微基准 | 容易隔离初始化函数本体 | 不能说明真实 consumer 总体成本与后续代价转移，不适合作本批结论 |

推荐形态复用 `dependency-comparison-tools/driver.mjs:2` 的 sample 行为；替换该文件
`:79` 起的双 slot 排程，以及 `child.mjs:51` 的双模块加载。原工具冻结不动，新工具在
独立私有目录准备。不是对 library 加 profiler/export。

所有 consumer 子进程串行，在同一个固定绝对路径 `run-slot/bundle.mjs` 导入一个版本。
父进程仅在上一个子进程已退出、证据归档并通过 verifier 后替换该槽位的字节。
B/C 原始 bundle 为不可变文件，槽位只是执行投影：进程条目绑定批准的原始散列，
导入前后核对槽位字节；不得把槽位当成来源真相。进程不得导入另一版本来预检。
固定 driver/input 路径、Node 绝对路径与散列、环境和 argv 形态，禁止 cache-busting query。
这消除双模块共存和 URL 角色差异；不保证内存地址、JIT 或 OS 状态相同。

## 3. 有限排程与测量单位

提议仅 P2-lifecycle 一行，8 个相邻四进程组，共 **32 个新进程**。
四组顺序 B-C-C-B，四组 C-B-B-C；从8组中选4组的70种安排等概率抽一次，准备时冻结。
每种顺序包含 B/C 各2次，整体每个位置都有B/C各4次；进程内只有一个测量块。
不先全跑 B 再全跑 C，也不在同一进程交错版本。

每进程保留该版本现有冷/动作语义预检（7个不计时实例），20 warmup、100 measured。
总计224预检实例、640warmup、3200measured，共3840生命周期样本。
从50改到100测量值只使 nearest-rank p95 取第95个（第6大），不承诺消除尾部不稳定。
预检也属于进程历史，两版本执行同形态预检；不得用观察曲线决定追加 warmup。

保留全部原始坐标和8个时钟，逐进程算 construction/initial/duplicate/cleanup/actionSum/
wall/residual 的p50、p95、sum。统计单位是进程与四进程组；3200样本不当作3200独立重复。
不汇总全部样本重新计算全局p95；不排除慢点，不拟合后扣除顺序系数。

每组对指标q（p50或p95）计算 R = sqrt(qC早 × qC晚 / (qB早 × qB晚))。
同时保留两种同版本时间对照：qB晚/qB早、qC晚/qC早。四进程对称顺序能平衡位置，
在对数耗时的线性时间漂移假设下两边平均时间位置相同；真实漂移未必线性，因此
不能宣称该公式自动校正机器噪声。同版本对照失败必须直接报告。

inactive-1 本次不新增采样：旧微秒级 release 的不稳定已保留；这轮用实际P2的两种
同版本时间对照检查噪声，不把不同时间尺度的release比值用作构造校正。

## 4. 在看新数据前固定报告规则

p50 与 p95 **独立**检查，每项指标分别有16个同版本晚/早比值和8个R。
沿用私有诊断的5%控制容许范围 [1/1.05,1.05]，作为建议待批准，不是D169预算。
控制全部在范围内，且8个R全部<1，才标“本次观察到一致下降”；全部>1为一致上升；
其他为mixed，任一控制越界则该指标为control-unstable/inconclusive。
报告全部比值与绝对值，不只中位数，不给显著性或总体置信区间声明。

允许“构造p50下降，p95未知”；必须原样呈现未知，不说整体性能通过。
初始输入、重复输入、清理和动作总量各自按相同规则报告；若上升则明确存在代价转移线索，
若控制不稳定则不能声称没有转移。RSS只报观察峰值/间隔，不给单graph或存活堆结论。
正式1.20/1.10预算、D169原方法、用户分级隐藏验收均不受影响。

数值结论在固定32进程结束后计算，不根据前几个好坏选择延长或补组。
任何语义错误、release/occurrence违规、源/运行时漂移、进程错误、证据失败或资源/时钟
条件触发，立即停止剩余进程；失败前缀不升级为完整比较，不自动重试或恢复。
如果完整结束仍控制不稳定，则结束此方法，保持unknown；不再用同形重复碰运气。

## 5. 准备资格、预算与证据

拟沿用观察RSS256MiB、每子进程30秒、全轮900秒、目标100ms轮询，wake不变、双时钟
相对偏差≤0.5秒、同子进程观察间隔≤1秒；父进程休眠期间不能实时强制，恢复后停止。
这些是建议的有限上限，不是新增运行授权。禁止强制GC、profiler、后台额外consumer。

后续工具准备先做零consumer资格：完整32假进程/3840假样本；验证70种平衡排程；
单模块导入计数；上一进程退出前不能换槽；错误版本/槽位漂移/路径漂移/重复claim拒绝；
既有中断、资源、时钟、截断证据与保留失败路径继续验证。固定Node选择必须在collector
内部绑定冻结绝对路径与散列，不再仅依赖本次外部PATH补偿。

独立Python verifier从不可变源、批准排程、子进程身份和原始样本重算统计；不加载library，
覆盖p50/p95方向不同、同版本控制失败、零分母与缺失子进程。源闭包重建/变更边界证明、
plain/reference语义预检、释放检查、原正确性和runtime mutation证据继续保留。
新工具资格不替代已批准library代码的行为证据。

归档必须保留各次槽位投影字节/散列、源证明、顺序、授权claim、运行时、原始样本、收据；
只读新解压回放重算逐字一致。准备完成才冻结具体资产digest，随后一次采集需单独批准。
本草案不启动工具实现、节点性能API、公共分层export、provider/live/spend或新D#。

## 6. Q5–Q9 审查

**Q5 — 层级与抽象。** 私有consumer测量器负责隔离实验条件，library不承担这个状态机。
复用sample边界及oracle，新增复杂度仅为父进程的有限排程和证据投影。graph拓扑仍是原有
真实consumer，不用微基准替代业务结果（graphrefly:D793）。

**Q6 — 长期风险。** 槽位是可变执行资源，必须单owner、无活跃子进程才替换，且证据不可变。
运行时更新、来源改动意味着旧冻结失效。新数据无法满足控制时即止，不把工具变成持续优化平台。
诊断标签与graphrefly-ts:D169正式资格隔离，后者仍未完成。

**Q7 — 简化与可组合性。** 每进程一个版本/一个块，去掉第二模块历史，不改graph dependency、
authority提交、lifecycle或dispatcher。父进程的命令式进程控制是私有评测边界，不进入用户API。
删去本轮无解释力的跨尺度微基准采样，保留真实动作后果及同版本对照。

**Q8 — 备选。** 双模块扩矩阵保留主要混杂；factory微基准牺牲consumer代表性。
选择单版本进程消除已知结构性混杂，接受无法完全消除跨进程噪声的限制；不额外叠加profiler。
先例是本项目已有新进程隔离、source proof、独立verifier和一次性claim，新增之处是单槽位及四进程配对。

**Q9 — 覆盖与建议。**

| 关注点 | 覆盖 | 残余风险 |
| --- | --- | --- |
| 双模块/第二块历史 | 是 | 跨进程状态仍不同 |
| 中心与慢尾分别可见 | 是 | 100样本p95仍可能不稳定 |
| 顺序影响 | 部分 | 对称排程不能消除非线性漂移，以对照失败收敛 |
| 可复核与授权 | 是，待工具资格 | 槽位生命周期与Node绑定必须验证 |
| 用户认知/性能负担 | library无新增 | 私有测量工具维护成本需保持有限 |
| 正式性能资格/分级隐藏 | 不覆盖 | 明确不宣称完成，不更改D169 |

推荐批准此设计后，只进入私有工具实现与假样本资格。若工具资格暴露无法满足的隔离条件，
先修复或回报，不自动增加复杂度；真实32进程采集待工具冻结后单独审阅。
