# 中立 driver：单次诊断结果

已完成批准的 12 个串行进程、28,800 样本（7,200 warmup / 21,600 measured），耗时 18.159823 秒；24 次原业务预检 / 72 个计时外实例，零重试、零 not-run。独立 verifier 逐样本重算一致。

结论：第三批 candidate 槽较慢的现象，在 hosted、中立 driver 和反转预检顺序三类条件中都保留。它不依赖于“一个本地调用、一个外部调用”，也不要求 candidate 是最后预检的 module。尚未分开批次调度与累积调用历史，更没有定位到某个 consumer 节点、GC 或 V8 机制。

这是固定预算的私有诊断，不是已冻结 CSP-11 / D168 正式矩阵重验。源派生限定在冷构造 P2/summary；两个原业务 bundle、输入、计时循环、schedule 和 cleanup 保持归档原文。普通用户没有新增入口或性能配置，library 没有代码改动。

## 工具资格与边界

- 先验证全部 88,800 个既有真实 cold 样本的原始 2/3-arm 顺序与字段，再验证 paired projection 的分位数。历史样本没有混入本轮统计。
- 独立 AST 检查器不导入 generator 或业务 bundle；逐段核对原文、允许的 guard/factory/preflight 修改、非 generator 声明，绑定 TypeScript parser 版本和源码 digest。
- 六个入口用实际加载的 stub 检查 import、预检、factory、cleanup 与 driver 身份。错误 row/control/slot/cell/order/copy 在任何业务导入前拒绝。改 driver 源码由实际观察和 exact-entry 校验检测。
- 四个中立条件另加载实际派生循环，在 fake clock / built-in 替身下检查 2,400 次构造的计时、record、cleanup 顺序；错误 factory、预检、缓存、cleanup、计时或 generator 变体均检测，双失败保留原始错误及 cleanup 错误。没有用 stub 代替正式子进程的原业务预检。
- 新 Python 5 项工具测试通过（53 个负例）；原 crossover 9 项 / 33 个负例通过。JS 9 个 AST 负例、14 个实际路径负例和 1 个双失败保留场景通过，4 个正例覆盖全部中立条件。两位静态审查者最终无剩余问题。
- lint / layer / typecheck 通过。全量 TS：2,547 通过、2 个已有 D159 frozen manifest 失败、4 跳过；没有把全量状态写成通过。无公共 API 变动，因此没有重复 build；library 原文件及 root 六个未提交文件保持不变。

## 后续判断

下一步值得单独设计的是在保持业务与计时定义不变的前提下，区分 block 调度和累积调用历史。已有证据足以缩小方向，但不足以直接选择一种正式公平测量方法。当前不追加采样、不改变阈值、不修改 runtime；CAUSAL-PRESET-ASSEMBLY-TS 仍未完成。原 v1 1.211671 拒绝、80 not-run 及 v2 inconclusive/control-instability 均保留。用户/agent 分级隐藏的易用性和 teach-back 仍未由本批证明。
