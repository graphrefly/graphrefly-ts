That size makes the artifact useful as opt-in audit/debug evidence, but unsuitable as default product telemetry; bounded production/debug profiles are deferred rather than being smuggled into this package-local eval.

## Read an observation

An exact envelope from line 30:

```json
{"path":"eval/observation/provider-effect-activity","msg":["DATA",{"kind":"eval-effect-class-activity-snapshot","effectClass":"provider","activeEffects":0,"activeExecutionIds":[],"admittedEffects":0,"settledEffects":0,"cleanupFailureCount":0,"completedTargetWorkItems":0}],"tier":3,"seq":31}
```

`path` names the actual producing node. `msg` is its protocol message; only DATA contains a business value. `seq` orders observer delivery, not business identity. The canonical occurrence stream is `eval/observation/canonical-state`: line 3921 contains `occurrenceRevision: 247`, the terminal coherent cut. Read its `occurrenceId/occurrenceRevision/occurrenceDigest/occurrenceSourceRefs` for correlation and its `value` for progress, active effects, budget, finding and stopping reason. `eval/observation` is the value projection of that same producer.

Transport contributions at `eval/observation/arrivals` retain per-source revisions. An exact older replay is quiet; a contradictory or skipped revision produces `eval/observation/rejections`. Observation rejection does not mutate admission/budget authority. A full observation is published only when its domain coordinates form a coherent cut; it is not promised for every individual internal contribution.

## Boundaries and remaining risks

The HTTP transport runtime is installed by the live-shaped executor into the same supplied Graph. The standard describe artifact above captures the core campaign topology with the scripted executor; HTTP-leaf topology/privacy is separately exercised by `root-eval-http-transport-leaf.test.ts`.

Join controllers have bounded graph/bundle-lifetime retention, not per-subscriber lifetime. Unsubscribing one public output does not reset its occurrence ledger. This implementation does not claim dynamic topology-group removal of those retained bundles.

An exploratory probe containing more than 13,184 repeated full diagnostic envelopes hit a 120-second CPU timeout (~849 MB worker RSS). It is **not a passing benchmark**. The actual 175-call campaign conservation test passes; pathological log-processing cost remains a diagnostic-profile/benchmark concern. The evidence bound is not a promise that processing every maximum-sized diagnostic trace is inexpensive. Product observation profiles and their CPU/RSS/log-size benchmarks are deferred to root backlog rather than changing the public API here.

The deterministic artifact's 5/5 relevant-versus-cold result is scripted identifiability evidence by construction (`claimStatus: no-network-identifiability-only`, `efficacyClaim: none`). D159's empirical attempts instead exposed a benchmark ceiling: Together could solve the synthetic targets without discriminating memory provenance. Those two results answer different questions and must not be combined into an efficacy claim.

## Test tiers

- `pnpm test` is the fast/default correctness gate. It retains the granular root-eval adapter, transport, budget, persistence and topology-contract suites, and excludes only `solutions-agentic-memory-work-item-root-eval-live.test.ts`.
- `pnpm run test:root-eval-soak` runs that monolithic 101-case live-shaped boundary/cohort suite explicitly. Use it for release qualification, changes to the root-eval lifecycle, or exhaustive soak—not again inside the same default test invocation.
- `pnpm run eval:root:artifacts:check` independently proves that the checked-in describe, observation and derived artifacts reproduce exactly.
